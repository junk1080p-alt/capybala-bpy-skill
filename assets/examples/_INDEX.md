# 組合範例庫 · 總目錄（主 skill §0.5 只載入本檔，範例檔按需讀取）

> 這個目錄回答的問題跟 `anatomy/`（組件清單）、`styles/`（美術方向）都不同：**這裡是
> 「把 shape_lib/mat_lib/geonodes_lib/road_lib/building_lib 這些工具組合起來，從空白
> 場景走到成品」的完整工作流程範例**，含真實可執行的程式碼順序、每一步該呼叫哪個
> 函式、以及這個主體品類特別容易踩的坑（都是這次調研+實測抓到的真實問題，不是
> 假設性的教學範例）。遇到同類任務時，先讀對應範例檔再動手寫場景腳本，不要憑
> 記憶重新設計流程——每個範例檔本身就是一份「已經驗證過順序正確」的骨架。
> **不限於單一物件品類**：`triview_reconstruction.md`／`space_scene.md` 這兩份是跨品類
> 的技術性工作流（三視圖複刻、太空場景配方），觸發條件是「有沒有這類參考資料/場景類型」
> 而不是「車/建築/馬路」這種物件品類——一樣照本檔案的使用流程處理，只是觸發詞欄位改填
> 觸發條件。

## 使用流程（強制）

1. Stage A 規劃階段：命中觸發詞 → `read_file_native`（或你的 agent 平台上等價的讀檔工具）讀對應範例檔 → 範例檔的「工作流程」
   段落直接決定 Stage A 簡報要列哪幾個建模步驟，不要自己另外發明順序。
2. Stage B 動工：範例檔的程式碼骨架可以直接複製進場景腳本改參數，**但函式呼叫方式/
   參數名一律以 `assets/<lib>.py` 目前的真實簽名為準**——範例檔的程式碼是「示範用法
   截圖」，lib 本體改了簽名時範例檔可能還沒同步更新，衝突時信 lib 原始碼。
3. 範例檔的「常見錯誤」段落是實戰踩過的真實坑，對照著檢查自己的場景腳本有沒有犯同一種錯。
4. 這個主體品類實戰又踩到新坑 → 回填對應範例檔的「常見錯誤」表（跟 `anatomy/`/
   muscle memory 同一套「單一真相源、實戰回填」機制，§9.3.5）。
5. 觸發詞命中但範例檔不存在（新品類，例如「畫一艘船」）→ 照 `_TEMPLATE.md` 現場寫一份，
   建完存回本目錄供下次復用——跟 `anatomy/_TEMPLATE.md`/`styles/_TEMPLATE.md` 建卡流程
   一致，不要因為沒有現成範例就跳過「寫完存回去」這一步。
