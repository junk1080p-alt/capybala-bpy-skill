# 組合範例模板（新品類照此格式，寫完存為 assets/examples/<品類>.md）

> 範例回答的問題：**這個品類實際動工時，該用哪幾個工具、按什麼順序、每一步容易在
> 哪裡犯錯**。跟 `anatomy/`（組件清單，回答「有什麼、在哪一面」）和 `styles/`
> （美術方向，回答「長什麼樣子」）是三件不同的事，三者互補使用：先查 anatomy 知道
> 要建哪些組件、查 styles 決定造型/色票方向、再照本檔的工作流程實際動手。

## 建立流程
1. 先查有沒有對應的 `anatomy/<品類>.md`（組件清單）——沒有就先照 `anatomy/_TEMPLATE.md`
   建一份，範例檔的工作流程要對應圖譜列出的組件，不能自己漏建。
2. 列出這個品類實際會用到的 lib 函式，按真實依賴順序排（例如「造型要先做完才能開窗，
   開窗要先做完材質才有東西可以套」），每一步都要是曾經**實際跑過**的程式碼，不是
   憑函式簽名腦補的用法——沒實測過的範例檔比沒有範例檔更危險（會誤導使用者相信一個
   沒驗證過的順序是對的）。
3. 每一步標注「為什麼選這個工具」——尤其是有多個工具都能達成類似效果時（例如開洞
   到底該用 `cut_hole`還是 `cut_window`，取決於 host 是不是薄殼），這個判斷依據要
   寫清楚，不要只寫「呼叫這個函式」。
4. 常見錯誤表只填**真的實戰踩過**的坑（自己開發/測試這份範例時發現的，或使用者
   實戰回報的），不要預先猜測填一堆「可能的錯誤」湊表格。
5. 每次實戰踩到新坑 → 回填「常見錯誤」欄（同 `anatomy/` muscle memory 機制）。
