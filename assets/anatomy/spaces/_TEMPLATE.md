# 空間類主體必備元素圖譜模板（新建空間類型照此格式，寫完存為 assets/anatomy/spaces/<空間類型>.md）

> 圖譜回答的問題：**這個空間類型「必備哪些元素、少了還算不算這個空間」**。
> 跟 `assets/anatomy/<品類>.md`（§13.7，管產品類主體的六面組件）是同一個問題
> 的姊妹版——差別是空間類主體沒有「六面」的概念，缺件的判準改用**功能分類 +
> 反思測試**：對每個候選元素問「拿掉這個，這裡還算是不算是這個空間類型？」
> 算 → 這個元素標 MUST（結構性/功能性必需，Stage A 簡報不准省略）；
> 不算 → 標 OPTIONAL（缺了觀感簡陋一點，但不影響空間仍然成立）。
>
> 為何要有這份圖譜：Stage A 簡報若一開始就沒把「動線」放進候選清單（只列黑板/
> 講台/桌椅/窗戶），後面任何比例公式或斷言都救不回來——**漏在規劃階段的東西，
> 驗證機制管不到**。本圖譜要解決的正是「規劃階段別漏掉」這一步。

## 模板正文（複製以下結構）

```markdown
# <空間類型> 必備元素圖譜
> 適用範圍：<具體場景類型，例如「亞洲高中/國中教室（30人以下）」>
> 依據來源：<真實案例/建築規範/使用經驗——寫清楚，不准憑空>

## 元素清單（分類 + 反思測試）

| 分類 | 元素 | MUST/OPTIONAL | 反思測試（拿掉後還算這個空間嗎？） | 落地要點 |
|---|---|---|---|---|
| 結構殼體 | 例：牆/地板/天花板/門 | MUST | 沒有牆就不是室內空間了 | |
| 功能核心物件 | 例：（該空間類型存在的理由本身，如教室的黑板、咖啡廳的吧台） | MUST | 拿掉後這個空間失去存在目的 | |
| 座位/工作站 | 例：桌椅/工作台 | 視人數需求 MUST | 沒有座位還是空間，但失去主要用途 | |
| **動線/走道** | **至少一條可通行路徑**，寬度達到最低標準（一般抓 ≥0.75-0.9m，對應常見建築規範的最小通道寬度） | **MUST，不可省略** | 沒有動線＝家具擋死通路，不是可用空間，只是倉庫 | 用 `T.assert_min_gap()` 驗證，不能只做「家具沒互相穿插」的最低要求 |
| 收納 | 例：置物櫃/層架 | 依空間需求 | | |
| 照明 | 例：燈具（不是只有光源，燈具本身是可見物件） | MUST（暗室不算完整空間） | | |
| 裝飾/氛圍 | 例：時鐘、布告欄、盆栽、風扇 | OPTIONAL | 拿掉這些，空間的「識別度」還在，只是少了細節 | |
```

## 建立流程

1. **先列全部候選元素，分七類**（結構殼體/功能核心物件/座位工作站/動線走道/收納/照明/裝飾），寧可多列、Stage A 階段再刪，不要一開始就用「印象中這個空間有什麼」自我審查漏列。
2. **每個候選元素都跑反思測試**：「拿掉這個，這裡還算不算是這個空間類型？」——算 = OPTIONAL，可以先做別的再回來補；不算 = MUST，Stage A 簡報不准跳過，Stage B 動工前要能在簡報裡指出它在哪、多大。
3. **動線永遠是 MUST，且要單獨驗證**：不是「家具間有間隙」就叫動線，是要有一條**明顯比其他間距更寬**的路徑，寬度用 `assert_min_gap()`（build_template.py，§13.8）驗證達到最低標準——任何空間類主體都適用，不是教室專屬。
4. **Stage A 設計簡報引用圖譜**：簡報的「必備元素清單」段直接從圖譜抄，MUST 項目缺一項就要在簡報裡明講理由或請使用者確認；OPTIONAL 項目可以列出但聲明「本次先不做」。
5. **每次實戰踩到新空間類型的坑** → 回填「常見錯誤模式」欄（同 muscle memory 機制）。
