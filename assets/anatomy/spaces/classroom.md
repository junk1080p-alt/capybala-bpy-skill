# 教室 必備元素圖譜
> 適用範圍：亞洲高中/國中教室（30-40 人座位規模，含講桌黑板正規教室，不含補習班小班制）
> 依據來源：亞洲高中教室實際使用經驗。

## 元素清單（分類 + 反思測試）

| 分類 | 元素 | MUST/OPTIONAL | 反思測試（拿掉後還算這個空間嗎？） | 落地要點 |
|---|---|---|---|---|
| 結構殼體 | 牆/地板/天花板/前後門 | MUST | 沒有牆不是室內空間了 | |
| 功能核心物件 | 黑板（或白板）+ 講台 | MUST | 拿掉黑板，這裡就只是一間空房間，不是教室 | 黑板/講台是教室存在的理由，Stage A 必須明確給出位置（通常前牆中央）與尺寸；**黑板不是一片光滑量體**——底部一定有粉筆槽（沿板寬一整條淺凹槽，`loop_cut`/`carve_depression`），槽內常見殘留粉筆+板擦；講台常見上緣一塊斜面（放課本方便閱讀角度）+ 內側收納格/抽屜（放粉筆盒/教具） |
| 功能核心物件 | 投影幕/布告欄（依現代教室慣例） | OPTIONAL | 沒有投影幕，仍是傳統教室 | 投影幕有的話配投影機（天花板懸吊或講桌上型，兩者擇一），單獨畫布告欄沒配投影機是合理的（傳統教室常見兩者只有布告欄） |
| 座位/工作站 | 學生課桌椅（一人一套，依班級人數） | MUST | 沒有桌椅就不是教室，是禮堂/走廊 | 網格陣列，人體工學硬尺寸（§12.5）優先於比例公式；**桌椅本身也有次組件，不是兩塊光滑板**——桌面下方常見一格開放式書包/課本收納格（金屬線架或木板隔層）、桌角掛書包的側邊掛勾、椅背常見弧形貼合背部（不是純平板）、桌腳末端常見防滑/防刮腳墊 |
| 座位/工作站 | 教師桌椅（講台旁） | MUST | 缺教師桌椅，教學無處立足 | 教師桌通常比學生課桌大、附抽屜（1-3 層側抽屜+桌面下方中央抽屜），桌上常見教師專用物品堆（點名冊/教科書疊放/馬克杯，屬於「生活痕跡」細節，選用但大幅提升真實感） |
| **動線/走道** | **至少一條中央或側邊主走道**（寬度 ≥0.75-0.9m），外加每排桌椅之間的基本通行間距 | **MUST，不可省略** | 沒有走道，學生進出、老師巡視都做不到——只是一堆桌椅堆在房間裡，不是可用教室 | 用 `T.assert_min_gap()` 驗證主走道寬度；桌椅網格的「等距最小間距」不能替代「一條明顯更寬的主走道」 |
| 收納 | 後方/側邊置物櫃或書包掛勾 | OPTIONAL（但常見） | 沒有置物櫃，仍是教室，只是收納不便 | |
| 照明 | 天花板日光燈/practical light | MUST | 暗室不算完整可用的教室 | 至少覆蓋全部座位區，不能只照亮黑板 |
| 照明 | 採光窗（自然光） | MUST（亞洲教室慣例） | 全黑無窗的房間不太會被認作「教室」，比較像倉庫/機房 | |
| 裝飾/氛圍 | 時鐘、風扇、盆栽、學生作品展示 | OPTIONAL | 拿掉風扇，仍是教室，只是夏天比較熱 | 牆掛時鐘常見位置：黑板正上方或側牆上緣；吊扇則在天花板均勻分佈 2-4 台（不是一台）；學生作品展示常見側牆整排磁性/軟木公佈欄，不是隨機貼幾張紙 |
| 亞洲教室特有 | 打掃工具角（掃把/畚箕/拖把） | OPTIONAL（但亞洲教室極常見） | 拿掉打掃角，仍是教室，但少了亞洲教室特有的生活感辨識度 | 通常在教室後方或側邊角落，掃把/拖把靠牆立放（`add_cyl` 細長桿+頭部量體），畚箕掛牆或立地 |
| 亞洲教室特有 | 班級門牌/座位表 | OPTIONAL（但常見） | 拿掉門牌，仍是教室，只是少了「這是幾年幾班」的身份標示 | 門外或門邊一小塊銘牌（`make_text()`），教室內後方常見座位表公告 |
| 安全設施 | 滅火器 | OPTIONAL（但真實教室法規常要求） | 拿掉滅火器，仍是教室，但真實場所這是法規常見要求的安全設施，容易被畫面忽略 | 後方或門邊牆面掛式紅色圓柱體+標示牌，`add_cyl`+`make_text()` 即可，小型細節但存在感強（紅色在中性色調教室裡很搶眼，加了立刻提升真實感） |

## 常見錯誤模式（實戰回填區）

| # | 錯誤 | 判讀方式 | 修正 |
|---|---|---|---|
| 1 | Stage A 簡報完全沒提到「動線/走道」這一項，直接跳過規劃階段；動工後桌椅網格用等距最小間距（0.65m 縫隙）填滿整個房間，肉眼看是擠成一團、沒有路可以走 | describe_image/CALIB 都抓不到這類「規劃階段漏掉一整個功能類別」的問題，沒有東西可以拿去跟一個根本不存在的規劃項目比對 | Stage A 強制對照本圖譜列出全部 MUST 元素，動線單獨用 `assert_min_gap()` 驗證（§13.8） |
| 2 | 黑板/投影幕物件本身確實建在房間正中央（x=0），但相機 `target` 刻意設在偏離中心 0.4m 的位置（理由是「留前景給窗光」），導致構圖上黑板看起來偏向畫面左側，跟簡報裡自己寫的「對稱系統，教室是秩序空間」自相矛盾 | 檢查 `Feat_Blackboard`/`Feat_Screen` 等物件的世界座標 x 是否真的是 0，若是則問題出在 `config.CAMERA["target"]` 而非幾何本身——這是「構圖選擇」蓋過「已宣告的設計系統」，不是穿模/擺位類的硬錯誤 | 選定對稱系統的空間類主體，相機構圖預設置中；如果為了前景/光線需要偏移，必須在 Stage A 簡報寫清楚理由，不要在沒有說明的情況下悄悄偏移 |
| 3 | `T.instance()` 傳 `rot_z=180.0`（度）但函式內部沒轉弧度，30 張椅子全部轉成 233.24°（180 弧度取餘），跟預期的 180° 差了 53°，肉眼判讀為「每張椅子都是歪的」 | 這不是空間規劃層級的問題，是共用範本 `build_template.py` 的 `instance()` 函式本身的單位轉換 bug（已修復，見該檔案的修正記錄） | 已修復：`instance()` 現在正確呼叫 `math.radians(rot_z)` |
