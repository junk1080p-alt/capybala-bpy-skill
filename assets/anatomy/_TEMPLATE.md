# 產品組件圖譜模板（新建品類照此格式，寫完存為 assets/anatomy/<品類>.md）

> 圖譜回答的問題：**這個產品品類的「哪一面有什麼、朝向如何、成對關係為何」**。
> §13 三問管單個組件的方向語義；本圖譜管整個品類的組件清單與空間分佈。
> 圖譜要防的是**品類知識缺件**：例如相機的光學觀景窗是前後雙窗的貫通結構，
> 只建正面那一半就會讀成「觀景窗裝錯面」。這類知識必須先寫成圖譜再建模。
>
> **圖譜是地板，不是天花板**：寫這份圖譜是為了「防止漏掉容易被
> 忽略的必要組件」，內容深度反映的是**寫圖譜當下查證/實戰踩坑的程度**，不是這個
> 品類所有可能細節的完整清單。建圖譜時盡量往深寫（能查到的真實拆解/型錄資料越
> 細越好）；日後任何模型讀到這份圖譜、如果自己對這個品類的認識比圖譜寫得更細，
> 一律以自己的判斷為準直接加上去，不要因為圖譜沒點名某個細節就假設不需要或這樣
> 才是標準答案——這點務必寫進每份圖譜自己的「建立流程」段，不要省略。

## 模板正文（複製以下結構）

```markdown
# <品類> 組件圖譜
> 適用範圍：<具體產品類型與年代>
> 依據來源：<實物照片/官方圖紙/工程常識——寫清楚，不准憑空>

## 座標公約
觀眾側 = -Y（相機側），主體正面朝 -Y（§12）。以下「左/右」一律指**觀眾視角**。

## 六面組件清單
### 正面（-Y，觀眾側）
| 組件 | 位置（比例座標） | 典型尺寸 | 功能語義/朝向 | 細節要求（detail_lib） |
|---|---|---|---|---|

### 背面（+Y，使用者操作側）
（同表結構）

### 頂面（+Z）/ 底面（-Z）/ 左側（-X）/ 右側（+X）
（同表結構）
```

## 建立流程
1. 有實物照片/官方圖 → 對照逐面列組件；沒有 → web search 該品類解剖圖（exploded view/teardown）。
2. 每個組件回答 §13 三問（給誰看/沿什麼方向/裝在哪面），寫進「功能語義」欄。
3. 成對組件單獨列表——**單面視角渲染看不到的組件是使用者誤判的高發區**。
4. **最低限度表現原則**（見 `car.md` 完整範例段落）：對每個組件自問
   「這個品類如果完全沒有這個部件，現實中還能不能正常運作/存在？」——能，是
   OPTIONAL；不能，是 MUST，即使不需要做出可動/可開闔機構，也至少要刻出分模線
   或做出對應的小型物件，不能完全省略幾何（車體必然有門+門把，即使不用真的能開）。
5. Stage A 設計簡報引用圖譜：簡報的組件清單以圖譜為底線起手，缺件在此步暴露——**圖譜是地板不是天花板**，模型自己知道的細節比圖譜寫得更深時直接加上去，不要因為圖譜沒提就跳過或以為那樣才是標準答案（見本檔開頭說明）。
6. 每次實戰踩到新品類坑 → 回填「常見錯誤模式」欄（同 muscle memory 機制）。
